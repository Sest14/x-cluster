# ADR-0014: 投稿とプロフィールは TwexAPI で集め、公式 X API は網羅性の検査だけに使う

- 日付：2026-11-19
- 状態：採用（ADR-0002 を置き換え。ADR-0009 と ADR-0011 の一部を置き換え）

## 背景
- 公式 X API は、ADR-0011 の設計でも約85〜90ドルかかる。ユーザーにとって負担が大きすぎた。
- TwexAPI（X社とは無関係の第三者の業者）は、投稿やプロフィールの読み取りが1件5クレジット（約0.00006ドル）で、公式の約100分の1。$10の Mini パックで800,000クレジット（7日で失効）。
- TwexAPI はスクレイピング系のサービスと考えられ、X の利用規約が想定する取得方法ではない。統計上は、取得の網羅性が保証されていないことが最大の問題になる。
- ユーザーの判断：公式な研究として発表するわけではないので、網羅性がある程度担保でき、ユーザー自身に被害が及ばないなら使ってよい。
- TwexAPI には件数確認の機能がない。投稿には投稿者のプロフィールが付いて返ってくる。

## 決定
**データ源**
- 投稿とプロフィールは TwexAPI の advanced_search で集める。時間の範囲は `since_time:`/`until_time:`（UNIX時刻）で指定する。2026-11-19 の `tcheck` で、この形式は指定した1時間の枠内の投稿だけを返し、`since:..._UTC` 形式は0件だったことを確認した。応答の項目名（`id`、`full_text`、`created_at_datetime`、`in_reply_to_user_id`、`quoted_status_id_str`、投稿者の `screen_name` など）もドキュメントどおりだった。
- 公式 X API は、(1) 日別の件数（`count`）、(2) 網羅性の検査（`coverage`）、(3) 抽出で選んだ群の重み（`weights`）にだけ使う。見積もりは合計5〜10ドル。

**集め方の変更**
- 6件（regista／bl_zoning／uma_mune／edamame／saito／touken）は、期間中の該当投稿を**全件**集める。全投稿者の一覧が手に入るので、そこから単純無作為抽出で各200人を選ぶ。抽出確率は全員同じになり、重み付けは要らない（ADR-0009 の重み付けを置き換え）。
- touken_fans と対照群は全件が多すぎるので、日別比例で1,000件を集め、その投稿者から200人を選ぶ。この2群だけ、公式APIの件数確認で重みを付ける。
- 「ふだん」は、件数確認の代わりに、炎上前（2026-09-15〜10-15）の投稿を実際に最大50件取って測る（炎上前の投稿がなければ直近30件）。日常語を含む割合は、取れた投稿から数える。判定ルール（ADR-0011）はそのまま使う。
- 二段階抽出のうち「第2段階で投稿を取る」部分はなくなる（全員分の投稿が取れるため）。第2段階は「Claude がアカウントの型を詳しく判定する抽出（各群25人）」として残し、第1段階のルールの的中率を測る（ADR-0012）。
- H3 の言及確認は、TwexAPI で「from:アカウント（5件のどれか）」を検索して確かめる。

**網羅性の検査（事前登録）**
1. 日別の比較：件ごと・日ごとに、TwexAPI で取れた件数と公式の件数を比べる。
2. 抜き取りの照合：件ごとに、公式APIで無作為な1時間の枠から10件ずつ、合計約100件の投稿を取り、TwexAPI の収集に含まれているかを確かめる。
3. 判定の基準
   - 照合で見つかった割合が90%以上：良好
   - 80〜90%：使うが、限界として明記する
   - 80%未満：その件は「参考値」とし、仮説 H1・H2 の検証には使わない
4. 偏りの確認：取れていた投稿と取れていなかった投稿で、返信・引用・メンションの割合を比べる。差が大きければ、どんな投稿が抜けやすいかを報告する。

**ユーザーに被害が及ばないようにすること**
- TwexAPI には X のアカウントを使わずにAPIキーだけでアクセスする。ユーザーの X アカウントは関わらない。
- クレジットは少額のパックで買う（まず無料の20,000クレジットで `tcheck`、本番は $10 のパックを1〜2つ）。失効期限（Mini は7日）内に収集を終える。
- 生データ（raw.sqlite）は PC の外に出さない。結果は集計値だけを扱い、アカウント名や投稿本文は出さない（ADR-0004）。
- 分析が終わったら `purge` で生データを消す（TwexAPI のデータは公式の削除への追従ができないため、長く持たない）。

## 検討した他の案
- 公式APIだけで最小版（約30ドル）にする：H1〜H3 は検証できるが、精度が下がる。
- 公式APIを一切使わない：網羅性を確かめる手段がなくなる。数ドルで検査できるので残す。

## 影響
- 費用は、TwexAPI 約10〜20ドル＋公式API 約5〜10ドル。
- 6件は全件が揃うので、やり取りのネットワークは期間中の全投稿者で作れるようになる。
- TwexAPI の検索がどこまで漏れなく返すかは、業者次第で変わりうる。網羅性の検査の結果を、すべての報告に添える。
- TwexAPI のサービスが止まった場合、取得済みのデータで分析を続ける。
