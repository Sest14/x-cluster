# ADR-0015: 起点の投稿は公式APIで集め、TwexAPI はアカウント指定の検索だけに使う

- 日付：2026-11-20
- 状態：採用（ADR-0014 を置き換え。ADR-0009 の日別比例抽出と重み付けを全群に戻す）

## 背景
ADR-0014 では、炎上の投稿を TwexAPI で全件集める予定だった。2026-11-19 の試験で、次のことがわかった。

| 試験 | 結果 |
|---|---|
| regista を1日単位で検索（11/5〜11/11） | 公式の件数の2〜10% |
| regista を1日単位で検索（11/12〜11/17） | 約60% |
| 11/5 0〜6時を6時間の枠1つで検索 | 4%（18 / 425件） |
| 同じ時間帯を1時間の枠6つで検索 | 22%（93 / 425件） |
| 11/5 0時台を10分の枠6つで検索 | 22%（19 / 88件） |
| 起点の投稿者10人について、炎上前の期間を `from:アカウント` で検索 | ほぼ100%（841 / 844件。100件を上限に比較） |

- TwexAPI のキーワード検索は、時間の枠を細かくしても2割前後で頭打ちになる。X の検索画面と同じように、一部の投稿が除外されている可能性が高い。そうだとすると、取れる2割は無作為ではない。
- 一方、アカウントを指定した検索（`from:`）は、ほぼ漏れなく返る。
- 事前に決めた網羅性の基準（80%未満の件は使わない。ADR-0014）により、TwexAPI のキーワード検索で集めた起点の投稿は分析に使わない。
- このとき、ユーザーの TwexAPI のAPIキーには、Mini パック購入後も「5秒に1回」の制限がかかっていた（サポートに問い合わせ中）。

## 決定
- **起点の投稿**：公式APIの全期間検索で、各群300件を日別の件数に比例して集める（ADR-0009 の方式）。
- **アカウント**：各群の起点の投稿者から200人を無作為抽出する。
- **プロフィールと@名**：公式APIのユーザー検索で取る（1人0.01ドル）。TwexAPI が `from:<数字のID>` を受け付けることが `tdiag fromid` で確認できたら、`resolve_via` を `twex` にして TwexAPI で取る。
- **ふだんの投稿・重み・H3の言及確認**：どれも TwexAPI の `from:` 検索で取る。重みは、調査期間中に自分の群の検索条件に当たる投稿の数（上限200件）とする。
- 試験で TwexAPI のキーワード検索で集めたデータは、`purge` で消してから本番を始める。

## 影響
- 費用：公式APIが約15〜30ドル（プロフィールを TwexAPI で取れれば下限側）。TwexAPI は購入済みのクレジットで足りる。
- 6件を全件集めないので、やり取りのネットワークは抽出した投稿の範囲でしか作れない。
- 重みを TwexAPI の `from:` 検索で数えるため、その網羅性（ほぼ100%）に依存する。抽出した人のうち無作為に選んだ一部で、公式APIの件数と照らし合わせる（`tdiag from`）。
- 5秒に1回の制限のままだと、収集に約12時間かかる。
