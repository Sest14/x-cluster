# ADR-0016: キーワード検索の2割頭打ちはX側の仕様と判断し、他社サービスへの乗り換えは行わない

- 日付：2026-11-21
- 状態：採用（ADR-0015 を補強。方針の変更はない）

## 背景
ADR-0015 で、TwexAPI のキーワード検索は公式の件数の2割前後で頭打ちになると判明した。原因が TwexAPI 固有の実装か、X 本体の検索の仕様かを特定するため、他社サービスと比較した。条件は ADR-0015 と同じで、regista の 2026-11-05 0〜6時（UTC）を1時間の枠6つで検索し、公式APIの件数（425件）と照合した。比較には `py xc.py pdiag` を使い、各サービスで取得した投稿IDを `raw.sqlite` の `diag_ids` に記録した（本文は保存しない）。

### 1. 5社の比較（`pdiag <サービス>`、`pdiag compare`）
| サービス | 取得率 |
|---|---|
| SocialData | 23%（96 / 425件） |
| TwexAPI | 20%（85 / 425件） |
| ScrapeBadger | 20%（86 / 425件） |
| TwitterAPI.io | 19%（82 / 425件） |
| Apify（`jacquemus~x-tweet-scraper`） | 19%（80 / 425件） |

- 5社の和集合でも24%（101件）。5社共通が77件で、2社ずつの重複率は79〜98%。
- どの社も X 本体の検索を中継しており、同じ約2割の投稿を返している。

### 2. 返信の有無（`pdiag twex ... split`）
| 区分 | 取得率 |
|---|---|
| 返信以外 | 22%（60 / 268件） |
| 返信 | 17%（27 / 155件） |

返信以外でも2割なので、「返信が除外されている」という仮説は棄却した。

### 3. アカウント単位か投稿単位か（`pdiag who`）
公式APIで同じ時間帯の投稿を投稿者ID付きで取得した（401件。検証開始から24件が削除済み。約2.4ドル）。2件以上投稿した43人について、投稿が全部見える／全部見えない／混在のどれかを数えた。

| 項目 | 結果 |
|---|---|
| 混在 | 14人 |
| 投稿単位で無作為に抽出した場合の期待値 | 18.8人（標準偏差 約3人） |

アカウント単位の除外なら混在はほぼ0になる。実測は期待値に近いので、X は**投稿単位で約25%を選んで**検索結果に出していると判断した。

## 決定
- 起点の投稿の収集は、ADR-0015 のとおり公式APIの全期間検索で行う。キーワード検索を他社サービスに乗り換えることはしない。
- TwexAPI は、ADR-0015 のとおり `from:` 検索（アカウント指定）にだけ使う。
- `pdiag` は、今後キーワード検索の網羅性を再確認するための診断用コマンドとしてリポジトリに残す。

## 検討した他の案
- **SocialData などへの乗り換え**：取得率は5社とも約2割で同じ投稿を返すため、乗り換えても改善しない。
- **複数社の結果を合算する**：和集合でも24%にとどまり、網羅性の基準（80%。ADR-0014）に届かない。

## 影響
- ADR-0015 の「取れる2割は無作為ではない」という推定は、アカウント単位の偏りについては否定された。ただし、投稿単位の選別が無作為か、内容による品質フィルターかは区別できていない。キーワード検索の結果を母集団の代わりに使わない、という結論は変わらない。
- 対象者は43人と少ないため、アカウント単位の影響が一部ある可能性は否定しきれない。
- `from:` 検索がほぼ100%返る（ADR-0015）ことと合わせると、X の除外はキーワード検索の段階でかかっていると考えられる。
- 見直す条件：X の検索の仕様が変わったとき。`pdiag` を再実行して取得率を確かめる。
- 検証に使った無料枠・有料分のおおよその費用：公式API 約2.5ドル、他社はいずれも無料枠の範囲。
