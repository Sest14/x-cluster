# 方法論：X上の発言とアカウントをどう分析し、どう数字にするか

このプロジェクトで、もっともらしく、しかも誤解を招かない統計を出すための前提知識と手順をまとめる。
数字を出す前に必ず目を通し、手順を変えるときは ADR に理由を残すこと（[docs/adr/](adr/)）。

---

## 1. 必要な知識

### 1.1 データの出どころ（X と X API の性質）
- **検索で取れるのは「いま公開されている投稿」だけ。** 削除された投稿、鍵垢、凍結・削除されたアカウントは取れない。全期間検索でも同じ。
- **日本語検索は単語ではなく文字列の一致に近い。** 「レジスタ」で検索すると「レジスター」も当たる。ノイズの混入率を必ず実測する（§2.3）。
- **第三者のデータ業者（TwexAPI など）は網羅性が保証されない。** 公式の件数や公式APIで取った投稿と照合して、取りこぼしの割合と偏りを測ってから使う（ADR-0014）。
- **画面で目に入る量と実際の量は違う。** 表示はおすすめアルゴリズムや引用RTの連鎖で偏るので、体感の「燃えている」は件数の根拠にならない。
- **API のデータには欠けているものがある。** 表示回数、ブロック・ミュート、DM、いいねした人の一覧などは基本的に取れない。
- **規約による制約。** 削除された投稿は手元でも削除する。個人のセンシティブな属性（政治的・思想的立場など）を個人単位で推定・プロファイリングしない。X のデータでモデルを学習させない。結果は集計値として扱う（ADR-0004、ADR-0007）。

### 1.2 調査設計（社会調査の基礎）
- **母集団を言葉で定義する。** 「似た発言をしている人」とは誰か。期間・言語・検索条件・立場の判定基準で定義し、その定義の外には一般化しない。
- **検索条件は「操作的定義」そのもの。** どの語を入れるかで、どんな人が入るかが決まる。たとえば「フェミ」を含めると、ある立場の人が多く入りやすくなる。
- **これは観察研究であって実験ではない。** 「サブ垢の人ほど攻撃的」のような関係が見えても、原因と結果は言えない。言えるのは「こういう傾向が観察された」まで。
- **妥当性と信頼性。** 測りたいもの（たとえば立場）を本当に測れているか（妥当性）。同じ手順で同じ結果が出るか（信頼性）。

### 1.3 テキスト分析
- **話題と立場は別物。** 「ゾーニング」という語を含んでいても、賛成・反対・皮肉・引用のどれもありうる。キーワードが一致しても賛同とは限らない。
- **日本語の処理。** 形態素解析（分かち書き）と文の埋め込み（文の意味をベクトルにする手法）。皮肉、伏せ字、隠語、画像だけの投稿には弱い。
- **立場の判定は人の判断を基準にする。** 判定基準書（コードブック）を作り、人が付けたラベルを基準として、自動判定の精度を測る。

### 1.4 ネットワーク分析
- **やり取りの種類ごとに意味が違う。** リプライと引用は反論や攻撃にも使われるので、「つながっている＝仲間」ではない。賛同に近いのはRTやいいねだが、RTは今回除外していて、いいねは取れない。
- **コミュニティ検出は不安定。** 解像度パラメータと乱数で結果が変わる。複数のシードとパラメータで回して、安定して出るクラスタだけを結論に使う。

### 1.5 アカウントの性質
- **サブ垢判定は推定にすぎない。** プロフィールの記述、話題の集中度、作成時期、フォロー比などから推定するだけで、確定はできない。
- **同じ人の複数アカウントは区別できない。** そのぶん人数を過大に数える可能性がある。これは限界として明記する（同一人物を突き止めることはしない。ADR-0004）。
- **bot・業者・まとめアカウントが混じる。** 除外の基準を事前に決めておく。

## 2. もっともらしい統計の出し方

### 2.1 事前登録：数える前に決める
収集・分析の前に [analysis-plan.md](analysis-plan.md) に次の項目を書き、コミットする。
- 問い（何を知りたいか）と仮説
- 母集団の定義、検索条件、期間
- 指標の定義（「アンチ」「サブ垢」「本垢運用」を何で判定するか）
- 除外基準（bot、日本語以外、宣伝など）
- サンプルサイズと抽出方法
- 主に見る比較（どの群とどの群を比べるか）

データを見たあとで定義を変える場合は、ADRで理由を残し、変更前の結果も併記する。

### 2.2 抽出と数え方
- **層化無作為抽出。** 検索条件ごとに同数を無作為に選ぶ（ADR-0006）。全体の比率を出すときは、層ごとの母集団の大きさで重み付けして戻す。
- **数えるのは投稿ではなくアカウント。** 1人が100件投稿してもその人は1人。投稿単位の集計を出すときは、上位何%の人が何%の投稿をしているかも必ず添える。
- **分母を必ず書く。** 「40%」ではなく「120人中48人（40%、95%信頼区間 31〜49%）」と書く。

### 2.3 判定の精度を測ってから数字を出す
1. 検索で当たった投稿から無作為に100〜200件を抜き出し、人がラベルを付ける。付ける項目は、関係あり／なし、立場（批判・擁護・中立・不明）、サブ垢らしさ。
2. 可能なら2人で独立にラベルを付け、一致度（コーエンのκ）を測る。0.6未満なら判定基準書を直す。
3. ラベルを付けるときは、どの検索条件から来た投稿かを伏せる（先入観を避けるため）。
4. 自動判定（ルール、または学習済みモデルをそのまま使う判定。X のデータで学習はさせない）の適合率と再現率をこのラベルで測る。
5. 誤判定の率がわかったら、その分を補正した比率を出す。

### 2.4 比べる相手を用意する
「批判側のサブ垢率40%」という数字だけでは意味がない。少なくとも次の群と比べる。
- 同じ件で擁護側に立つアカウント
- 対照群：同じ期間に、話題と関係ない一般的な日本語投稿をしたアカウントを無作為に抽出したもの

### 2.5 不確実性を示す
- 比率には信頼区間を付ける（ウィルソン法、またはブートストラップ法）。
- 50人未満の群は「参考値」と明記する。20人未満の群は比率を出さない。
- 群の差を検定するときは、効果の大きさ（比率の差とその信頼区間）を主に示す。p値は補助にとどめる。

### 2.6 探索と確認を分ける
- いろいろな切り口でデータを眺めると、偶然でも何か「差」が見つかる。眺めて見つけた仮説は、別のデータ（別期間、別の件）で確かめる。
- 多くの検定をするときは多重比較の補正をかける（ホルム法、またはベンジャミニ＝ホッホベルク法）。

### 2.7 感度分析
次の条件を変えても結論が保たれるかを確かめ、変わるなら結論を弱める。
- 検索語（1語ずつ外して再集計する）
- 期間（ピークの前後で分ける）
- 判定の閾値
- クラスタリングの解像度と乱数シード

### 2.8 再現性
- 結果には、コードのコミットハッシュ、config.json、乱数シード、データを取得した日時を必ず添える。
- 集計を出すスクリプトはリポジトリに入れる。手作業の集計はしない。

## 3. 統計のマジックに引っかからないためのチェックリスト

数字を出す前に、次の各項目を確かめる。

| 罠 | 例 | 対策 |
|---|---|---|
| 選択バイアス | 検索語の選び方で、特定の立場の人ばかりが入る | 立場が中立な語で集める。立場は後から判定する。語を変えた感度分析 |
| 生存者バイアス | 攻撃を受けて鍵をかけた・消した人が落ち、残った人だけを見ることになる | 欠けている部分の存在を限界として明記する。取得できなかった率を記録する |
| 声の大きさバイアス | 少数のヘビー投稿者がクラスタの性格を決めてしまう | アカウント単位で数える。投稿数の偏りを示す |
| 見えやすさバイアス | 「大炎上」と言われても実数は少ない | 母数（その話題の全投稿数や一般の投稿数）と比べる。§3.1 |
| 分母のすり替え | 割合と実数を都合よく使い分ける。グラフの軸を切り詰める | 実数と割合を併記する。軸はゼロから始める |
| シンプソンのパラドックス | 全体では差があるのに、件ごとに見ると逆になる | 層別の結果と全体の結果を両方出す |
| 生態学的誤謬 | 「このクラスタは攻撃的」→「この人は攻撃的」と個人に当てはめる | 集団の傾向として報告し、個人の評価には使わない |
| 定義の滑り | 途中で「アンチ」の定義を広げて数字を大きくする | 定義を事前に登録する。変えるならADRを書く |
| p値ハッキング・後付けの仮説 | 有意になる切り口だけを報告する | 事前登録と、探索・確認の分離。試した分析は全部記録する |
| 混入 | bot、業者、無関係な同名の話題（「レジスタ」の別の意味など） | 除外基準を決め、人のラベルで混入率を実測する |
| 相関と因果の混同 | 「サブ垢だから攻撃的」と言ってしまう | 「観察された」という言い方に留める |
| 分析者の確証バイアス | 自分の立場に都合のよい結果だけを掘ってしまう | ラベル付けを盲検化する。反対の結果が出たらどう解釈するかを先に書いておく |

### 3.1 参考例：「炎上」の実数を測ると
2021年、ウマ娘が「女性蔑視だと批判殺到」と報じられた件で、鳥海不二夫氏が実際の投稿数を数えた。該当する投稿は数十件で、ウマ娘全体の投稿のごく一部だった。しかも、目立った「炎上クラスタ」は批判している人たちではなく、「批判を批判する」人たちだった。「燃えている」という印象は、どの立場の人にとっても過大になりやすい。この分析では、どの立場の人数についても、必ず母数と比べて示す。
（出典：鳥海不二夫「『ウマ娘』の非実在型炎上をデータから見る」Yahoo!ニュース エキスパート https://news.yahoo.co.jp/expert/articles/6b484c5c37fb56cb2c9817eb882e9f901416871f ）

## 4. 結果を報告するときの書式

報告のたびに、次の項目を埋める。

```
問い：
母集団の定義（期間、言語、検索条件）：
抽出方法と人数（層ごと）：
除外したもの（件数と理由）：
指標の定義と判定精度（適合率、再現率、κ）：
結果（実数／分母、割合、95%信頼区間）：
比較の相手（対照群）：
感度分析の結果：
限界（取れないデータ、推定の不確かさ）：
再現情報（コミットハッシュ、config、乱数シード、取得日時）：
```

## 5. 倫理と公開の範囲
- 結果は集計値で示す。個別のアカウント名や投稿本文は示さない。例示が必要なときは、意味を保ったまま言い換えた文にする。
- 群の人数が少なく個人が推測できる場合は、その群を出さない。
- 生データ（raw.sqlite）、仮名化の鍵（salt.secret）、トークン（.env）は収集用のPCの外に出さず、リポジトリにも入れない（ADR-0008）。
